# 2026-09-21 审计修复：改了什么、怎么上线

本地 92 项测试通过（原 75 项 + 新增 17 项，`board/test_fixes.py`）；`check` 和 `makemigrations --check` 无问题。尚未部署。

## 改动

1. **匿名回复删除后泄露真名**：通知新增 `actor_anonymous` 字段，在创建通知时写死，模板不再依赖评论是否还在。迁移 0009 回填历史数据：评论还在的照抄其匿名状态；评论已删、无法确认的，一律按匿名处理（教师仍能看到真名）。
2. **缩略图**：帖子图片上传时额外生成最长边 1200px 的 WebP 缩略图，并按 EXIF 方向转正、去掉 EXIF/XMP（含 GPS）。首页卡片、详情页、编辑页封面选择都用缩略图；详情页点击图片打开原图。**原图一个字节都没动**，原有“保留元数据”的设计和测试保持不变。缩略图生成失败不会阻止发帖，页面会退回显示原图。
3. **媒体缓存**：每张图片的原图和缩略图地址返回 `Cache-Control: private, max-age=86400`，同一台设备翻页、返回时不再重新下载；HTML 页面仍然是 no-store。旧的 `/posts/<id>/image/`（封面地址会随封面变化）和音频保持不缓存。
4. **SQLite WAL**：`journal_mode=WAL`、`synchronous=NORMAL`、`transaction_mode=IMMEDIATE`。读不再被写阻塞。已验证：root 运行的备份脚本或 manage.py 创建 `-wal/-shm` 文件时，SQLite 会自动把属主改成数据库文件的属主，不会复现 9 月 16 日那种 root 属主导致的写入失败；备份包在 WAL 下数据完整。
5. **访问记录瘦身**：图片、音频和 `/healthz/` 不再写 VisitLog，一次首页从最多 21 次写入降到 1 次。资料下载仍然记录。
6. **登录限流**：新增同一 IP 15 分钟内失败总数上限 50 次（所有账号合计），挡住从外网按学号列表逐个猜密码。原有“同账号 + 同 IP 5 次”保留。
7. **默认密码提示条**：仍在用默认密码的学生，每个页面顶部会出现一条提示和修改链接；改密后消失。每个会话只检查一次，不影响性能。不强制。

## 更正上一轮审计里的一句话

上一轮我说按 IP 限流“专治拿学号挨个撞”，这句不对。用默认密码登录是一次就**成功**的，失败次数限流挡不住；而全班在同一个校园网出口 IP 后面，合法地登录 80 个不同账号，看起来和撞号一模一样。所以新的 IP 上限只防外网脚本猜已改过的密码。只要默认密码还在用，“同学登录同学账号”就只能靠改密解决，提示条是目前不强制情况下能做的最多的事。

另一处：锁定后正确密码也进不去 15 分钟的问题没改。放开它等于限流失效；同一出口 IP 下有人恶意锁别人账号时，教师可以在后台“登录失败记录”里删掉该学号的记录，立刻解锁。

## 上线步骤（服务器上以 root 执行）

用原来的 `install.sh` 流程即可，它会先备份、再迁移、补缩略图、收集静态文件、修正属主、重启：

```bash
# 1. 上传整个源码目录（同以往，排除 .venv/ data/ private/ .env* staticfiles/）
# 2. 在上传目录里执行：
bash deploy/install.sh 123.57.56.38
# 3. 确认缩略图数量：输出里有一行 created=N failed=0
ls /var/lib/course-square/media/post-thumbs | wc -l
# 4. 确认数据库已是 WAL，文件属主正确：
ls -l /var/lib/course-square/ | grep sqlite
```

上线后浏览器验收：首页图片正常、手机竖拍照片方向正确；详情页点图打开原图；用一个还在用默认密码的测试账号看到顶部提示；匿名回复一条再删除，被回复的人通知里显示“匿名同学”。

## 回退

迁移 0009 只加了两列，旧代码不读这两列，所以切回上一个 release 不需要恢复数据库：

```bash
systemctl stop course-square
ln -sfn "$(cat /opt/course-square/previous-release.txt)" /opt/course-square/current
systemctl start course-square
```

WAL 模式写在数据库文件里，旧代码同样能用，不需要改回。
